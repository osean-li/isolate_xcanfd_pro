# 固件开发环境搭建（HPM5321 隔离 USB‑CAN FD）

> 适用硬件：本仓库 `hardware/*.epro2` 网络表对应的实物板
> - 主控：**HPM5321**（RISC‑V RV32，480MHz，QFN48）
> - 隶属 **HPM5300 系列**（SDK 的 `soc` 用 `HPM5300`，board 配置以 `hpm5300evk` 为蓝本）
> - 功能：隔离 USB‑CAN/CAN‑FD 适配器（兼容 PCAN‑FD PRO）
> - 烧录接口：**仅 UART0 串口 ISP**（QFN48 无 USB‑Boot 引脚）
> - 调试接口：H1 的 SWD/JTAG（1‑4 脚）+ 板载 USB‑C
>
> 数据来源：`src/sdk_env/README_zh.md`、`docs/烧录与接线速查.md`、`src/sdk_env/user_template/`、SDK 目录实测。

## 0. 总体结论（先看这段，省时间）

- **不用** `git clone hpm_sdk` —— `src/sdk_env/hpm_sdk/` 已内置完整 SDK（2 万+ 文件）。
- **不用** 单独装 cmake / ninja / gcc / python3 —— `src/sdk_env/tools/`、`toolchains/` 已带齐。

- **阶段二（自研固件）** 用 `start_gui.exe` 或 `start_cmd.cmd` 进入环境，从 `hello_world` 最小示例起步。

## 2. 安装待装项（仅 3 件）

### 2.1 USB‑TTL 串口驱动
- 插上你的 USB‑TTL 模块，Windows 设备管理器若出现黄色感叹号，装对应驱动（CH340 用 `CH341SER`，CP2102 用 `CP210x`，FT232 用 `FTDI VCP`）。
- 目的：让电脑识别烧录用的 `COMx`。**与 FT2232 驱动是两回事**。

### 2.2 FT2232 驱动（调试用，可现在装好备用）
- 双击运行：`src/sdk_env/tools/FTDI_InstallDriver.exe`
- 用途：仅当你用 OpenOCD + FT2232 调试器做 GDB 调试时才需要。阶段一烧录**不依赖**它。

### 2.4 用 VS Code 写固件代码的完整流程

> 统一用 **CMake Tools 插件** 管理环境、IntelliSense、编译；所有路径以仓库根 `c:/wk/code/isolate_xcanfd_pro` 为例。
> 本流程针对已生成的工程 `src/my5321/`（含 `user_app/` 与 `user_board/`）。VS Code 只是**编辑器 + 前端**，编译用 SDK 自带 cmake/ninja，烧录用 HPMicro 工具。

**第 0 步 · 装好插件（§2.3 方案 A）**
在 VS Code 扩展商店（Ctrl+Shift+X）装：`C/C++`、`CMake`、`CMake Tools`、`Embedded Tools`、可选 `Cortex-Debug` / `RISC-V Support` / `serial monitor`。装完重启 VS Code。

**第 1 步 · 打开工程**
VS Code → `文件` → `打开文件夹` → 选 `src/my5321/`（仓库根，不是里面的子目录）。打开后先确认资源管理器能看到 `user_app/` 和 `user_board/`。

**第 2 步 · 配置工具链（关键，一次性）**
仓库**尚未**自带 `.vscode/settings.json`，需自己建。在 `src/my5321/` 下新建 `.vscode/settings.json`，内容如下（路径已按本仓库写死，可整段复制）：

```json
{
  "cmake.toolchainFile": "${workspaceFolder}/../sdk_env/hpm_sdk/cmake/toolchain.cmake",
  "cmake.cmakePath": "${workspaceFolder}/../sdk_env/tools/cmake/bin/cmake.exe",
  "cmake.generator": "Ninja",
  "cmake.configureOnOpen": true,
  "cmake.buildDirectory": "${workspaceFolder}/user_app/build",
  "cmake.configureEnvironment": {
    "HPM_SDK_BASE": "${workspaceFolder}/../sdk_env/hpm_sdk",
    "GNURISCV_TOOLCHAIN_PATH": "${workspaceFolder}/../sdk_env/toolchains/rv32imac_zicsr_zifencei_multilib_b_ext-win/bin",
    "PATH": "${workspaceFolder}/../sdk_env/tools/cmake/bin;${workspaceFolder}/../sdk_env/tools/ninja;${env:PATH}"
  },
  "cmake.configureArgs": [
    "-DBOARD=my5321",
    "-DBOARD_SEARCH_PATH=${workspaceFolder}/..",
    "-DCMAKE_BUILD_TYPE=flash_xip"
  ]
}
```

> 为什么必须这样配：
> - `toolchainFile` 强制用 RISC‑V gcc，绕过 CMake Tools 扫描不到编译器的问题。
> - `toolchain.cmake` 靠 `GNURISCV_TOOLCHAIN_PATH` 定位 gcc，靠 `HPM_SDK_BASE` 定位 SDK，两者都要注入。
> - `cmakePath` 指向 SDK 自带 cmake，避免系统 cmake 版本不兼容。
> - **`BOARD_SEARCH_PATH` 是关键**：自定义 board `my5321` 在 `src/my5321/`，**不在** SDK 的 `hpm_sdk/boards/` 里。SDK 的 `application.cmake` 只会在 `BOARD_SEARCH_PATH` 指向的**父目录**下按 `*/my5321.yaml` 查找（`BOARD_SEARCH_PATH=${workspaceFolder}/..` 即 `src/`，下面有 `my5321/` 子目录）。不设这个变量就会报 `No board named 'my5321' found`。**不要**把 `BOARD` / `CMAKE_BUILD_TYPE` 放进 `configureEnvironment`——CMake Tools 的 variant 会自动注入 `CMAKE_BUILD_TYPE=Debug` 与之冲突，故改放到 `cmake.configureArgs` 里强制覆盖。
> - 若路径与本机不符（尤其 `toolchains/` 子目录名），先核对再改。本仓库已核实：
>   - `src/sdk_env/toolchains/rv32imac_zicsr_zifencei_multilib_b_ext-win/`（gcc 工具链目录名，随 SDK 版本可能变）
>   - `src/sdk_env/tools/cmake/bin/cmake.exe`、`src/sdk_env/tools/ninja/ninja.exe`
>   - 一键核对（在仓库根执行，全部相对路径）：
>     ```bat
>     cd src\sdk_env\toolchains && dir /b
>     cd ..\tools && dir /b cmake\bin\ninja.exe 2>nul & dir /b ninja\ninja.exe 2>nul
>     ```
>   把 `dir /b` 输出的工具链目录名替换进 `GNURISCV_TOOLCHAIN_PATH` 即可，其余路径保持相对 `${workspaceFolder}` 不变。

**第 3 步 · 编写代码**
- `user_app/src/main.c`：应用逻辑（demo 已含「打印 + LED 闪烁 + CAN0 回环」）。
- `user_board/pinmux.c`：引脚复用（UART0 / CAN0），`user_board/board.h`：板级宏。
- 光标放函数上按 `F12` 跳转到 SDK 驱动（如 `can_init` → `hpm_sdk/drivers/inc/hpm_can_drv.h`）。跳转失败多半是第 2 步环境变量没配对。

**第 4 步 · 编译**
- 底部状态栏点 `Build` 按钮，或 `Ctrl+Shift+P` → `CMake: Build`。
- CMake Tools 会先用上面的环境跑 `configure`（生成 `user_app/build`），再 ninja 编译。
- 产物：`user_app/build/my5321_demo_hpm5300_flash_xip.bin`。
- ⚠️ 若报 "file name too long"，是 Windows 长路径限制——把工程移到盘符根目录（如 `D:\xcanfd\`）再打开编译（见 §6）。

**第 5 步 · 烧录（串口 ISP）**
板子**没有 USB‑Boot**，只能用 UART0 串口 ISP。两种方式任选：

- **命令行**（VS Code 集成终端 `` Ctrl+` `` 里执行，用了绝对路径不依赖环境）：
  ```bat
  cd /d c:\wk\code\isolate_xcanfd_pro\tools\HPMicro_Manufacturing_Tool_v0.6.0
  hpm_manufacturing_cmd.exe -p -r "load-image c:\wk\code\isolate_xcanfd_pro\src\my5321\user_app\build\my5321_demo_hpm5300_flash_xip.bin"
  ```
- **图形界面**：双击同目录 `hpm_manufacturing_gui.exe` → 芯片类别选 **HPM5300** → 载入上面的 `.bin` → 连接/烧写（详细见 §3.2）。

> 烧录前接线：USB‑TTL（拨 3.3V）TX→H1.5、RX→H1.6、GND→H1.7；**按住 SW1** 上电进 ISP 再松开。

**第 6 步 · 看串口**
`Ctrl+Shift+P` → `Serial Monitor: Open` → 选 `COMx`、波特率 `115200`，看到 `hello from my5321`（或 `tick`）即运行正常。

**第 7 步 · 调试（可选）**
`start_gui.exe` 点「启动 GDB Server」→ VS Code 左侧「运行和调试」配 Cortex‑Debug（见 §4.6）→ `F5` 下断点。需先装 FT2232 驱动并接 SWD/JTAG（H1 的 1‑4 脚）。

## 3. 阶段一：用官方固件验证硬件链路（不编译）

> 目标：确认 MCU、晶振、电源、CAN 收发、隔离都正常，再进入自研。

### 3.1 接线（详见 `docs/烧录与接线速查.md`）
- **USB‑TTL ↔ H1 排针**（交叉接，模块拨 3.3V）：
  - TTL `TX` → H1 pin5（`DBG_RX`）
  - TTL `RX` → H1 pin6（`DBG_TX`）
  - TTL `GND` → H1 pin7（`GND`）
  - TTL 的 3.3V/5V **不接**（板子由 USB‑C 供电）。
- **BOOT 按键**：SW1 按住 = BOOT0 拉高 = 进 ISP。
- **CAN 线束**：CN1/CN2 的 pin2=CANHx、pin1=CANLx、pin3=ISO_GND（隔离地，勿与 USB 侧短接）；终端电阻用 SW2 切换。

### 3.2 烧录
1. 解压 `tools/HPMicro_Manufacturing_Tool_v0.6.0.zip`，运行 `hpm_manufacturing_gui.exe`。
2. **按住 SW1** → 接 USB‑C 上电 → 出现 COM 口后松开。
3. 工具选该 COM 口 → 载入 `firmware/FDFW_20260201.bin` → 连接/烧写。
4. 成功 → 松开 SW1 → 断开 USB‑C 重插 → 设备管理器出现 PCAN 类设备。

### 3.3 验收
- PCAN‑View / TSMaster 发一帧 `123#DEADBEEFCAFEBABE`，确认回环/收发。
- 量 CAN 侧地与 USB 侧地应**不导通**（隔离成立）。

## 4. 阶段二：基于 HPM SDK 自研固件（从最小示例起步）

> 学习策略（按你定的顺序）：
> **官方最小示例（hello_world）→ 自建 board → GPIO/UART → CANFD 裸驱动 → 最后才参考 `reference/pcan_pro_x`（STM32 版，只学协议与功能构成，不能编译进 HPM）。**

### 4.1 打开 SDK 环境
双击 `src/sdk_env/start_cmd.cmd`。该窗口内已设好 `HPM_SDK_BASE`、工具链、cmake/ninja。所有编译命令都在此窗口执行。

### 4.2 跑通第一个官方示例（hello_world）
用图形界面（零配置）：
1. 双击 `src/sdk_env/start_gui.exe`。
2. Board Path 选 `hpm_sdk/boards/hpm5300evk`（5321 属 5300 系列，用它作蓝本）。
3. Application Path 选 `hpm_sdk/samples/hello_world`。
4. Build Type = `flash_xip`。
5. 点 **Generate** → **Compile**。产物：`hello_world_hpm5300evk_flash_xip/build/*.bin`。

> 此时已验证：SDK + 工具链 + cmake 全链路 OK（用最接近 5321 的 5300 board）。

### 4.3 自建 board 骨架（user_template）
SDK **没有 hpm5321 原生 board**，需基于 `user_template` 自建：
1. 复制 `src/sdk_env/user_template/` → `src/my5321/`。
2. 编辑 `my5321/user_board/user_board.yaml`，关键字段：
   ```yaml
   board:
       name: my5321
       soc: HPM5300          # 5321 属 HPM5300 系列
       device: HPM5300xEMx
       openocd-soc: hpm5300  # 见 hpm_sdk/boards/openocd/soc/
       openocd-probe: ft2232 # 或 cmsis_dap / jlink
       on-board-flash:
         type: qspi-nor-flash
         size: 16M           # 按实物 Flash 容量填
       on-board-ram:         # 无外置 SDRAM 则不写
       feature:
   ```
3. 编辑 `user_board/board.c` / `pinmux.c`：按本板原理图配置 UART0（烧录/调试串口）、CAN0/CAN1 引脚复用与时钟、收发器使能 GPIO。
4. `user_app/src/main.c`：从 `hello_world` 的 `main()` 起步，逐渐替换为自己的初始化逻辑。

> 参考蓝本：`hpm_sdk/boards/hpm5300evk/` 下的 `board.c` / `pinmux.c` / `board.h` / `board.yaml`，照着改即可。

### 4.4 编译自研工程（二选一）
- **GUI 法**：`start_gui.exe` → Board Path 选 `src/my5321/`、App Path 选 `src/my5321/` → Generate → Compile。
- **命令行法**（在 `start_cmd.cmd` 窗口）：
  ```bat
  cd src\my5321\user_app
  cmake -G Ninja -B build -DBOARD=my5321 -DCMAKE_BUILD_TYPE=flash_xip
  cmake --build build
  ```

### 4.5 烧录自研固件
- 同 3.2，载入 `src/my5321/user_app/build/*.bin`。
- 或命令行：`hpm_manufacturing_cmd.exe -p -r "load-image build\xxx.bin"`。

### 4.6 调试（可选）
`start_gui.exe` 内置「启动 GDB Server（OpenOCD）」，配合 FT2232/JLink 调试器或 VS Code + Cortex‑Debug 下断点。

## 6. 关键注意事项

- **soc 用 HPM5300**：本仓库 SDK 的 `hpm_sdk/soc/` 下只有 `HPM5300`，无 `hpm5321` 目录；5321 是 5300 系列的 QFN48 型号。
- **串口烧录无动态 reset 识别**：reset 后请手动断开重连 USB‑TTL。
- **长路径风险**：Windows 路径超 250 字符会让 ninja 失败。建议把工程放到盘符根目录（如 `D:\xcanfd\`）或缩短目录名。
- **电平**：USB‑TTL 必须 3.3V 逻辑；H1 排针无 3.3V 脚，板子由 USB‑C 供电。
- **隔离地勿短接**：CN1/CN2 的 pin3（ISO_GND）与 USB 侧 GND 不导通才是隔离有效。
